# Как читать трейс ожидания

Три источника смотрят на один и тот же простой. Их нельзя подменять друг другом.

1. `MONITOR` говорит, какую команду Redis получил. `LPOP` внутри `EVAL` — это опрос. `BRPOP` и `XREADGROUP BLOCK` — Redis держит соединение, пока не появится элемент или не истечёт таймаут.
2. `wchan` потока говорит, в каком сне ядра стоит поток. `hrtimer_nanosleep` — `time.sleep` или другой таймер. `ep_poll` — поток в `epoll`. `futex_wait_queue` — поток ждёт другой поток или таймер tokio. `pipe_read` — ждёт пайп родителя, не Redis.
3. py-spy называет Python-кадр, если интерпретатор вообще есть в процессе. У simple-q ожидание задачи живёт в tokio. Python-кадр в этом процессе — встроенный цикл, он в простое не забирает задачу.

`pickup_ms` из JSON — одно число на один запуск. Оно зависит от того, в какой точке периода ушло сообщение. Один замер не равен периоду. `sent_ms` в этих файлах берётся до запуска `python -m bench.cli`. Сотни миллисекунд до первой команды Redis в `MONITOR` относятся к этому процессу. Серия сдвигов и разрез по штампам — в {doc}`/reference/phase-series`.

Команды клиента, который делает `enqueue`, тоже попадают в `MONITOR`. `SUBSCRIBE celery-task-meta-...` после отправки — это результат Celery у отправителя. К ожиданию воркера она не относится.
