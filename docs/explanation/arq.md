# Почему arq опрашивает sorted set

Числа — в {doc}`/reference/arq`.

Воркер — один цикл asyncio в одном потоке. Каждые `poll_delay` секунд (0.5 по умолчанию) он делает `ZRANGEBYSCORE` и засыпает остаток интервала через `asyncio.sleep`. Поток в снимке стоит в `ep_poll`: и сон, и ответ Redis ждут на селекторе того же цикла. Второго потока, который держал бы GIL, нет.

261 мс при интервале 500 мс — попадание в текущий шаг. Сообщение, пришедшее сразу после `ZRANGEBYSCORE`, ждёт почти весь интервал. Сообщение, пришедшее перед следующим чтением, ждёт миллисекунды. Подписки нет: постановка — `ZADD`, воркер узнаёт о ней на следующем чтении.

p50 386 мс на пачке из 80 (`docs/bench.md`) лежит у того же интервала 0.5 с. Это не `BRPOP`.
