# Почему arq опрашивает sorted set

Числа — в {doc}`/reference/arq`.

Воркер — один цикл asyncio в одном потоке. Каждые `poll_delay` секунд (0.5 по умолчанию) он делает `ZRANGEBYSCORE` и засыпает остаток интервала через `asyncio.sleep`. Поток в снимке стоит в `ep_poll`: и сон, и ответ Redis ждут на селекторе того же цикла. Второго потока, который держал бы GIL, нет.

261 мс при интервале 500 мс — попадание в текущий шаг. Серия фаз 0–0.45 с повторяет пилу: pickup падает вместе с фазой и между 0.15 и 0.20 с прыгает с 134 на 571 мс. Разрез одного воркера читает `arq:queue` каждые 501 мс, а файл пишется через 1.4 мс после того `ZRANGEBYSCORE`, который уже видит `ZADD`. Двадцать три интервала на простое лежат в 500.4–501.6 мс: шаг `poll` стабилен, сон занимает почти весь `step`. Числа — в {doc}`/reference/phase-series`. Подписки нет: постановка — `ZADD`, воркер узнаёт о ней на следующем чтении.

p50 386 мс на пачке из 80 (`docs/bench.md`) лежит у того же интервала 0.5 с. Это не `BRPOP`.
